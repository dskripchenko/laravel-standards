# Сквозные тесты

Правила — `E2E-01`–`E2E-04` в `AGENTS.md`. Здесь — как их применять.

## Где они лежат

В репозитории продукта, отдельным проектом, который не импортирует
приложение:

```
tests/e2e/          # или qa/, тот каталог, который уже есть
  pyproject.toml
  uv.lock           # или lock-файл, который проект уже коммитит
  conftest.py
  scenarios/
  pages/
  docs/data-testid.md
  docs/findings.md
  docs/coverage-plan.md
```

Каркас forge — исключение (`E2E-01`). Там запускают `@playwright/test` на
TypeScript, включая первый набор. Остальное из этой главы остаётся:
отдельный коммит, `data-testid`, нет блокировки слияния, один записанный
прогон.

Проекты на Python используют pytest, pytest-playwright и Allure. Стартовый
`pyproject.toml` — в `templates/e2e-pyproject.toml`. Версии закрепляют те,
которые проект реально ставит, и коммитят lock-файл.

## Что сценарий может знать

Адрес стенда — из окружения. Значения `data-testid` — из
`docs/data-testid.md` этого проекта тестов. Синтетические пользователи.
Больше ничего. Ни класса модели, ни компонента Vue, ни SQL.

Новое поле или кнопка получают `data-testid`, который говорит, что это
(`project-name`, `archive-submit`). Строка в справочнике появляется в том
же изменении. Шаблон — `templates/data-testid.md`.

## Когда их запускают

Тестировщик, локально:

| Намерение команды | Что запускается |
| --- | --- |
| smoke | короткий путь одного продукта |
| regress | регресс одного продукта |
| all | все сценарии одного продукта |

Базовый адрес — аргумент или переменная окружения, а не хост, вписанный в
тест. Прогон по расписанию — следующий шаг. По умолчанию результат сквозных
тестов не блокирует слияние (`E2E-03`). Проект может явно включить стадию
CI; включённая красная стадия — это провал. Отсутствие стадии не отменяет
свидетельства выполнения работы из `E2E-04`.

## Что сдаёт автор изменения экрана

В том же запросе на слияние, отдельным коммитом:

1. Сценарий, добавленный или обновлённый.
2. Новые `data-testid` и строка справочника.
3. Заметка об одном локальном прогоне: имя окружения стенда, команда и
   исход. Если стенд недоступен, вместо исхода записывают конкретную
   причину. Секреты и персональные данные не вставляют.

Сбой, найденный при написании сценария и не исправленный в этом запросе,
идёт в `docs/findings.md` (`templates/e2e-findings.md`). Дефект продукта —
задача в трекере. Файл находок задачу не заменяет. Неуспешный или
невозможный локальный прогон сам по себе не блокирует слияние (`E2E-03`);
явно включённая красная стадия CI блокирует.

## Флаги

Сценарий, которому нужен конкретный вариант, использует тестовый заголовок
проекта и отладочный токен из окружения (`FLAG-02`). Токена в наборе нет.
Продакшен-стенды заголовок не принимают.

## План покрытия

`docs/coverage-plan.md` в проекте сквозных тестов перечисляет продукты и
сценарии, которые у них должны быть. Это план, не условие слияния. Шаблон —
`templates/coverage-plan.md`.
