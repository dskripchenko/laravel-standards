# dskripchenko/laravel-standards

База правил для проектов на PHP, Laravel и Vue: как писать код, как устроено
приложение, что можно и чего нельзя, как оформлять документы и какие пакеты
разрешены. Проект перекрывает и дополняет эту базу своим ADR, `AGENTS.md` и
`CLAUDE.md`.

Пакет — библиотека Composer без PHP-кода и без autoload. Установка ничего
не запускает и приложение не меняет. На диск попадает только этот текст.

Модели читают [`AGENTS.md`](../../AGENTS.md) в корне пакета (только
английский). Каркасы — в [`shapes/`](../../shapes/forge.md), рецепты — в
[`recipes/`](../../recipes/README.md), шаблоны для копирования — в
[`templates/`](../../templates/project-passport.md). Развёрнутые главы с
примерами — [`docs/`](../README.md), тоже по-английски. Здесь — перевод
для человека. Если перевод и `AGENTS.md` расходятся, верны `AGENTS.md` и
английская глава.

## Установка

Когда пакет есть на Packagist или в другом репозитории Composer, который
проект уже использует:

```bash
composer require dskripchenko/laravel-standards
```

Пока пакета нет на Packagist, Composer смотрит на локальную копию. Если
приложение лежит рядом с этим репозиторием, в `url` стоит `../laravel-standards`:

```json
{
    "repositories": [
        {
            "type": "path",
            "url": "../laravel-standards",
            "options": {
                "symlink": true
            }
        }
    ]
}
```

```bash
composer require dskripchenko/laravel-standards:@dev
```

Из любого другого места укажите в `url` относительный путь к этому
каталогу. `symlink: true` оставляет установленное дерево равным рабочей
копии: после `git pull` стандартов новый `composer update` не нужен.

Composer предупредит, что у пакета нет секции autoload. Так и задумано.
Секцию не добавляйте.

## Как сделать пакет базой

Правила действуют, когда проект сам на них ссылается. Вставьте импорт ниже
в **оба** файла в корне проекта: `AGENTS.md` и `CLAUDE.md`. Нет файла —
создайте. Импорт стоит первым. Паспорт и исключения проекта — под ним.
Полный блок — в [`templates/claude-import.md`](../../templates/claude-import.md).

```markdown
@vendor/dskripchenko/laravel-standards/AGENTS.md
```

Строка на английском сознательно: её читают модели. Путь всегда
`vendor/dskripchenko/laravel-standards/AGENTS.md`, в том числе если Composer
поставил пакет симлинком. Не копируйте `AGENTS.md` в проект. Копия устареет,
файл в `vendor` — нет.

Модель, которая открывает репозиторий, начинает с `AGENTS.md` или
`CLAUDE.md` проекта, читает импорт, затем применяет паспорт и то, что
записано под ним.

## Что главнее

`CORE-01`. Сверху вниз:

1. Закон и правила каждого сервиса, которого касается изменение.
2. ADR в каталоге ADR проекта.
3. `AGENTS.md` и `CLAUDE.md` проекта, включая паспорт.
4. Домашний handbook, если проект по нему собран и ведётся.
5. Этот пакет: `AGENTS.md`, затем `shapes/<каркас>.md`, затем `docs/`.

Допустимы четыре каркаса. Паспорт называет тот, который у репозитория.
Смешивать их в одной задаче нельзя. См. [архитектуру](architecture.md).

## Состав пакета

| Путь | Для кого |
| --- | --- |
| `AGENTS.md` | Модели. Английский. Правила с кодами, без длинных примеров. |
| `shapes/` | Модели. По файлу на каркас приложения. |
| `docs/` | Модели и люди. Английские главы с примерами. |
| `docs/ru/` | Люди. Те же главы по-русски. |
| `recipes/` | Модели. Короткие процедуры частых задач. |
| `templates/` | Люди и модели. Файлы, которые копируют в проект. |
| `composer.json` | Composer. Тип `library`, `php` — `*`, без autoload. |

## Обновление

Поднимите ограничение в приложении
(`composer update dskripchenko/laravel-standards`) или сделайте `git pull`
в этом каталоге, если пакет подключён путём. Затем прочитайте
`CHANGELOG.md`. Снимок markdown в приложение не копируйте.
