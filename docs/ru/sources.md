# Источники

Правила этого пакета взяты из двух практик, которые сходились в стеке и
расходились в устройстве приложения. Расхождение записано как четыре
допустимых каркаса (`SHAPE-01`). Его не замазывают.

## Домашний handbook

Handbook — набор правил для приложений с базовыми классами слоёв, Orchid и
Feature-Sliced Design. Где говорят и этот пакет, и handbook, проект каркаса
handbook следует своему handbook и своему ADR (`CORE-01`). Этот пакет —
база под ними.

Практика git из handbook (коммиты слияния, без rebase и без squash) и
разделы его документов — источник `GIT-01` и `DOC-02`.

## Домашние приложения и пакеты

Каркас forge — это приложения с `app/Domain`, `app/Api` и
`dskripchenko/laravel-api`. Каркас laravel-admin — приложения на
`dskripchenko/laravel-admin`. Старый каркас — приложения, которые группируют
код по технической роли и которые не переписывают внутри задачи на функцию.

Пакеты, которые уже закрывают задачу, перечислены в `DEP-04`. Как вызывать
пакет, по-прежнему написано в его собственном репозитории. Здесь сказано
только, когда за ним тянуться.

## Чего в этом пакете нет

Раскладка хостов, порты, какой контейнер что запускает, и текст внутренних
ADR остаются там, где этим управляют. Правило разработки, которое те
документы тоже содержат (закреплённые версии образов, секреты вне git и вне
аргументов команды, лицензии OSI, пока владелец не записал исключение,
никакого SQLite, Valkey за протоколом Redis, закон и правила каждого
внешнего сервиса), повторено здесь, чтобы оно было и у проекта, который
развёрнут в другом месте.
