# Безопасность

Эти правила стоят поверх умолчаний фреймворка. Выключить умолчание — это
исключение проекта (`CORE-01`), записанное в паспорте или в ADR. Тихое
отключение в одном месте вызова не годится.

## Секреты и персональные данные

Секрет читают из окружения внутри файла конфигурации и больше нигде.

```php
// config/services.php
return [
    'gitlab' => [
        'token' => env('GITLAB_TOKEN'),
    ],
];
```

```php
$token = config('services.gitlab.token');
```

`env()` не вызывают из контроллера, задачи очереди, тестового помощника и
файла Vue. В git не попадают `.env`, ключ, сертификат и дамп.
`.env.example` перечисляет все ключи с пустыми значениями.

В журнал не пишут пароль, хеш пароля, токен, номер карты и государственный
идентификатор (`SEC-03`). Строка журнала несёт идентификатор, исход и
идентификатор запроса. Журнал валидации фиксирует, какие поля не прошли,
а не значения, которые человек ввёл.

`SEC-07`. Персональные данные маскируют в журналах, в письмах и в списке
админки, который не является карточкой самой записи. Продукт записывает,
сколько каждый вид данных хранится, и удаляет или обезличивает их, когда
срок кончился. Чтение или изменение персональной записи пишет строку
журнала доступа: кто, когда, какая запись, что произошло. Перед коммитом
запускают сканер секретов, например gitleaks.

Примеры, фикстуры, снимки экрана, данные сквозных тестов и документы — на
синтетических значениях. Настоящая персональная запись в коммите —
инцидент, а не замечание на ревью.

## Вход и права

Пароли — `Hash::make` и `Hash::check`.

Каждый маршрут, который меняет состояние, проверяет политику или право
проекта на сервере. Спрятанная кнопка проверкой не является. Идентификатор
в запросе не доказывает владение: выборка ограничена вызывающим.

На маршрутах с cookie CSRF остаётся. Одностраничное приложение того же
сайта использует сессию Sanctum и cookie `XSRF-TOKEN`. Токен для машины
имеет только те возможности, которые нужны этой машине, и его можно отозвать.

Точки входа и публичные записи ограничены по частоте.

## Ввод и вывод

Массовое заполнение идёт через `$fillable` или `$guarded = ['id']`.
`$guarded = []` запрещён.

Значения в SQL связаны параметрами. В команду оболочки пользовательский
ввод не подставляют: передают список аргументов. Загруженный файл хранят
под сгенерированным именем, со списком допустимых типов и пределом размера.

`v-html` не отрисовывает текст, который ввёл человек, если только это поле
уже проходит санитайзер проекта и задача — именно про это поле.

Исходящий запрос идёт на хост, который приложение ожидает. Адрес из
запроса сверяют со списком разрешённых, прежде чем его запрашивать.

Ошибка API не содержит трассировку, текст SQL и секрет. В production
`APP_DEBUG=false`. Отладочные панели без аутентификации снаружи не открыты.

## Зависимости

`composer audit` и `npm audit` — условия слияния. Незакрытая уязвимость
уровня high или critical останавливает изменение. Флаг, который превращает
провал аудита в успех, не ставят.

Лицензии зависимостей — одобренные OSI. Всё остальное требует ADR владельца.

В lock-файлах нет адреса частного кеша, loopback и внутреннего прокси
(`DEP-06`). В файле остаётся публичный адрес реестра.

## Инварианты, которые касаются кода

- Версии образов закреплены (`STACK-02`).
- Секреты не передают аргументами командной строки (`SEC-02`).
- Новый публичный маршрут — явное решение (`CORE-08`), а не умолчание.
- Правила GitHub, GitLab, npm, Packagist и любого другого сервиса, к
  которому обращается изменение, — часть задачи (`CORE-02`). Только
  официальные API. Обход контроля доступа запрещён.
