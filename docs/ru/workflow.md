# Процесс

## Зависимости

Прежде чем добавить пакет, по порядку:

1. Это умеют Laravel, PHP, Vue или стандартная библиотека?
2. Это уже умеет пакет `dskripchenko/*` или `@dskripchenko/*`?
3. Вендор доверенный? Списки — в `DEP-01`. Tailwind — только там, где он
   уже есть. Новые стили следуют `FE-03`.
4. Иначе у пакета не меньше 400 000 установок (всего на Packagist или за
   неделю на npm), релиз за последние 12 месяцев, совместимость со стеком
   и чистый аудит.

Затем фиксируют lock-файл и запускают аудит. В npm lock-файле остаётся
публичный адрес реестра (`DEP-06`). Адрес частного кеша, loopback или
внутренний прокси, который записал кеш, вычищают. Отладочные и тестовые
пакеты остаются в `require-dev` (`DEP-07`). `composer.phar` в репозиторий
не кладут (`DEP-08`).

Свой пакет не обязателен только потому, что он существует. Он обязателен,
когда проект его уже выбрал: вторую библиотеку на ту же задачу не добавляют.

Версии для новой работы — `STACK-01`: PHP 8.5, Laravel 13, PostgreSQL 18,
Valkey 9, Node.js 24, Vue 3.5. Существующее приложение может оставаться на
минимуме из той таблицы. Основную версию не поднимают в том же изменении,
что и функцию, если задача — не про обновление.

## Git

`GIT-01`–`GIT-04`. В `main` попадают только коммиты слияния, из
просмотренного запроса на слияние, с зелёным пайплайном и решёнными
обсуждениями. Сливает владелец. Rebase, squash и force-push запрещены.
`main` зависит от выпущенных версий своих пакетов.

| Проект | Ветка |
| --- | --- |
| Есть ключ трекера | `<КЛЮЧ>-<slug>` или форма, которую записал паспорт |
| Ключа нет | `feature/<slug>` для реализации |
| Изменение постановки | `design/<slug>` |

Тема коммита на английском. Это форма трекера или Conventional Commits.
Номер задачи — в конце темы, потому что `#` в начале строки git считает
комментарием:

```
fix(projects): keep the archived flag on save (#22)
```

Тело в одну–три строки говорит, что изменилось, когда темы мало. Секреты,
дампы и внутренние имена хостов не коммитят.

## CI

Условие слияния — пайплайн запроса на слияние. Он гоняет формат, типы,
тесты, покрытие и аудит по коду, которого коснулось изменение. Сквозные
тесты в это условие не входят (`E2E-03`). Изменение только в документах
может пропустить задачи кода. Задачу защиты данных — нет.

Задача, которая не смогла выполниться, падает. Её не помечают как
допустимый провал, и порог не снижают ради зелёной доски.

## Закон и правила площадок

Работа остаётся в рамках закона и правил сервисов, которыми она
пользуется. Путь — официальные API и описанные интеграции. Где у сервиса
нет API, а правила запрещают автоматизацию, шаг делает человек; изменение
готовит данные или инструкцию.

Серая зона — не «наверное можно». Неясность называют и останавливаются.

## Как подключить эти стандарты

Проект зависит от пакета и импортирует
`vendor/dskripchenko/laravel-standards/AGENTS.md` из своих `AGENTS.md` и
`CLAUDE.md`. Строка и паспорт — в `templates/claude-import.md` и
`templates/project-passport.md` в корне пакета. Текст после импорта
перекрывает и дополняет пакет (`CORE-01`). Стандарты в приложение не
копируют.

Версии самого пакета стандартов следуют `STD-01`. В паспорте записана
версия, которой проект следует.
